# experts4bit-qlora

### Fine-tune large MoE models on a single GPU.

[![PyPI](https://img.shields.io/pypi/v/experts4bit-qlora)](https://pypi.org/project/experts4bit-qlora/)
[![CI](https://github.com/pjordanandrsn/experts4bit-qlora/actions/workflows/ci.yml/badge.svg)](https://github.com/pjordanandrsn/experts4bit-qlora/actions/workflows/ci.yml)

**Quantize the experts. Train adapters. Move weights to RAM or SSD when GPU memory runs out.**

**On a 12 GB card:** with `OFFLOAD_EXPERTS=1`, Qwen3-30B-A3B QLoRA-trains TC1's matched set (fp32 adapters, seq 2048,
r 16) at micro-batch 1 × accum 8 at 10.463 GB peak allocated on an RTX A2000 12 GB, while the rest of its packed experts
stay in pinned CPU RAM (`e4b.train.frontier.qwen3.a2000-12gb.2026-10-02`, one draw; micro-batch 2 ran out of memory on
that shared card). [The command](#load-a-model-and-check-it) ·
[how to read the number](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/docs/STORAGE-MODES.md#reading-the-headline-memory-numbers)

Mixture-of-Experts (MoE) models keep many expert networks but activate only a few per token.
Their fused expert weights can escape ordinary `load_in_4bit=True` loading and stay in full precision.
This runtime loads those weights in 4-bit, trains them with QLoRA, and serves the model.

**New here? [Start with Loggetta](https://github.com/pjordanandrsn/loggetta).**
`pip install loggetta` installs this runtime and its kernels. Use `loggetta inspect` to check your machine
and `loggetta plan` to plan supported training.
Use this package directly when you need control over loading, training, serving, or memory placement.

> **Limits.** GPU execution needs Linux and NVIDIA CUDA; the fast kernels need an sm_80+ GPU. Support varies by model
> family and execution path. 4-bit saves memory but is not automatically faster than bf16, and vLLM was faster in the
> measured Qwen decode comparison. [Check the fit](#check-the-fit).

## Install

```bash
pip install "experts4bit-qlora[train,fast]"
```

GPU execution needs **Linux + NVIDIA CUDA**. Fast kernels need an **sm_80+ GPU**,
Triton ≥ 3.4; the streaming loader needs transformers ≥ 5.0. The base runtime needs torch ≥ 2.2;
the fast extra applies the kernel package’s newer PyTorch floor.
CI tests Python 3.11. Start with a CUDA-compatible PyTorch installation for your GPU.

For a smaller install, the base package provides quantization and adapters; `[train]` adds the trainer;
`[fast]` adds [grouped-nf4-gemm](https://github.com/pjordanandrsn/grouped-nf4-gemm).
Exact dependency floors live in [pyproject.toml](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/pyproject.toml).

## Load a model and check it

This downloads Qwen3-30B-A3B and keeps its frozen experts in host RAM. Allow enough RAM and disk space for the checkpoint.

```python
import torch
from experts4bit_qlora import load_moe_4bit_streaming, verify_moe_4bit

model, config = load_moe_4bit_streaming(
    "Qwen/Qwen3-30B-A3B", "cuda", torch.bfloat16,
    r=8, alpha=16, quant_type="nf4", offload=True,
)
verify_moe_4bit(model, strict=True)  # raises if an expert stack stayed high precision
```

To train the built-in Alpaca example:

```bash
MODEL=Qwen/Qwen3-30B-A3B OFFLOAD_EXPERTS=1 STEPS=150 R=8 TRAIN_EXPERTS=1 OUT=./out python -m experts4bit_qlora.train
```

For your own dataset and reusable native adapters, see [Loggetta's training guide](https://github.com/pjordanandrsn/loggetta/blob/main/docs/TRAINING.md).

## New in 0.57.0

- **The paged server serves a trained adapter.** `E4B_PAGED_ADAPTER=<dir>` loads one attention adapter. The server
  verifies the directory before it reads any weight (paths, sizes, sha256, tensors, shapes, dtypes, finiteness), merges
  the attention LoRA into the bf16 projections at load, so serving it adds no per-token work, and refuses to start,
  naming each reason, rather than serve the base model in the adapter's place. Expert LoRA is refused for now. `/health`
  reports the adapter's id, manifest hash and merge report.
- **An adapter can carry a manifest the server checks.** `backend-adapter/2` records a canonical fingerprint of the
  quantized base (scheme `qfp-v1`: the same base fingerprints alike whether its NF4 absmax is stored nested or
  expanded), the training facts that decide whether serving is exact, and the LoRA scale actually applied; the server
  checks every field and refuses by name a manifest it cannot accept. Comparing the expert base's fingerprint at serve
  time is the next step; until then that check stays an explicit opt-in refusal.
  [`docs/ADAPTER_PORTABILITY.md`](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/docs/ADAPTER_PORTABILITY.md)
  states, from code, which training and serving pairings are exact, bounded behind a registered gate, or refused.
- **gpt-oss expert LoRA, opt-in.** `E4B_GPTOSS_EXPERT_LORA=1` wraps gpt-oss's experts for LoRA on the unfused
  reference loop, graded against an independent oracle on CPU. It refuses `offload`, and its speed against a fused
  route is unmeasured.
- **The plan prices the loss the run takes.** When the chunked LM loss refuses an LM head whose width differs from the
  configured vocabulary, the planner now prices the stock loss, as the run does.

## New in 0.56.0

Serving defaults on `qwen3_moe`. Each was measured alone on Qwen3-30B-A3B on one RTX 5090 (170 SMs); their combined
effect has not been read. Two need a newer grouped-nf4-gemm than `[fast]` installs (0.43.0 or later): K25's prmt decode
needs 0.50.0 and the int8 head needs 0.48.0. Below those each resolves off, recorded, and nothing breaks. To get them,
run `pip install -U grouped-nf4-gemm`.

- **Sixteen requests decode 1.0925× as fast, one request unchanged, every token identical.** (The smallest of four ABBA
  pairs.) K25, the batched NF4 decode GEMM, now decodes its codebook with grouped-nf4-gemm K39's byte-permute decode
  (`lut="prmt"`), bit-identical to the select tree it replaces. It needs grouped-nf4-gemm 0.50.0 or later and an NVIDIA
  device; otherwise it resolves to the tree, recorded in `info["k25_lut"]`. `E4B_K25_LUT=tree` opts out.
  ([P158](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p158/RESULTS-p158.md), `e4b.serve.p158.k25-prmt.qwen3.5090.2026-10-20`)
- **One request decodes 1.052× as fast from the lm_head on its per-row int8 grid** (the smallest of four ABBA pairs;
  grouped-nf4-gemm K36; at
  Qwen3-30B-A3B's 151936 x 2048 head only; needs grouped-nf4-gemm 0.48.0 or later, else it resolves off). **Outputs
  change:** the logits differ from the bf16 head's, inside the quality gates read on Qwen3-30B-A3B @ad44e777. Sixteen
  requests read 0.992, a cost not yet attributed. `E4B_INT8_HEAD_BW=0` restores the bf16 head.
  ([P153](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p153/RESULTS-p153.md), `e4b.serve.p153.int8-head-bw.qwen3.5090.2026-10-19`)
- **One request decodes 1.044× as fast with the paged FP8 attention decode capped at 16 splits** (the smallest of four
  ABBA pairs; buckets 1, 2 and 4 move; bitwise-identical to the library's plan at contexts up to 1024). Sixteen requests
  are unchanged. `E4B_ATTN_SPLIT_CAP=0` opts out.
  ([P143](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p143/RESULTS-p143.md),
  `e4b.serve.p143.attn-split-cap.qwen3.5090.2026-10-19`)

Training, opt-in. Each was measured on the card named, against the baseline its bullet names.

- **Layer-major training under expert offload steps 2.365× as fast on Qwen3-30B-A3B on one RTX 4090** (the smaller of
  two ABBA pairs of median step times). `layer_major_step` (`experts4bit_qlora.engines.layer_major`) runs a step's
  micro-batches layer by layer, so each offloaded layer is staged once per step instead of once per micro-batch. It
  replicates at 2.311× on an RTX 5090 and holds on Mixtral-8x7B at 2.118× on an RTX 4090, each the smaller of two ABBA
  pairs of median step times. Opt-in.
  ([P137](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p137/RESULTS-p137.md),
  `e4b.train.p137.layer-major-offload.qwen3.4090.2026-10-18`;
  [P140](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p140/RESULTS-p140.md),
  `e4b.train.p140.layer-major-offload.qwen3.5090.2026-10-18`;
  [P144](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p144/RESULTS-p144.md),
  `e4b.train.p144.layer-major-offload.mixtral.4090.2026-10-18`)
- **The CLI trainer can take the fused training path.** In 0.55.0, `python -m experts4bit_qlora.train` always ran the
  reference loop. `FAST_TRAIN=1` now puts it on the fused path, and `LAYER_MAJOR=1` implies it. At the CLI's own default
  recipe on Qwen3-30B-A3B with `OFFLOAD_EXPERTS=1`, `LAYER_MAJOR=1` steps 1.455× as fast as `FAST_TRAIN=1` alone on one
  RTX 4090 (the smaller of two ABBA pairs of median step times). An explicit `FAST_TRAIN=0` keeps the reference loop.
  ([P146](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p146/RESULTS-p146.md), `e4b.train.p146.layer-major-cli.qwen3.4090.2026-10-18`)

Mixtral serving.

- **Mixtral-8x7B decodes with its B=1 fold stack by default.** The T1 glue, its second round and the router epilogue now
  resolve to `auto` on Mixtral; fused q/k/v does not engage on this family. A one-request step takes 0.9393 of its time
  without them (median step time, the larger of two interleaved blocks) (about 20.2-20.5 ms to 19.0 ms) on one RTX 5090.
  Opt out per knob: `E4B_FUSE_T1_GLUE=0`, `E4B_FUSE_T1_GLUE_R2=0`, `E4B_FUSE_ROUTER_EPI=0`.
  ([P135](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p135/RESULTS-p135.md), `e4b.serve.p135.fold-speed.mixtral.5090.2026-10-18`)
- **`E4B_SERVE_ATTN_INT8=1`: int8 weight-only attention projections on Mixtral, opt-in.** q/k/v/o are held in int8 with
  a per-row fp32 scale, and decode calls of 1-16 rows run grouped-nf4-gemm's K37 kernels (from 0.49.0). On one RTX 5090
  the served read decodes one request 1.161x as fast (the smallest of four ABBA pairs) and sixteen 1.018x, with decode
  quality inside its registered bound. It stays opt-in until a routing-matched read: the default-flip PR is held.
  ([P149](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/bench/p149/RESULTS-p149.md),
  `e4b.serve.p149.int8-attn.mixtral.5090.2026-10-20`)

## Check the fit

- **Models:** use the [architecture support matrix](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/docs/ARCHITECTURE_SUPPORT.md). Support and test coverage vary by family and execution path.
- **Memory:** CPU/NVMe offload trades transfer time and host storage for GPU memory. Measure your workload.
- **Speed:** 4-bit saves weight memory; it is not automatically faster or more energy-efficient than bf16 when both fit.
- **Serving:** vLLM was faster in the measured Qwen decode comparison. This runtime focuses on fitting and controlling low-bit MoEs; see the [serving results](https://github.com/pjordanandrsn/experts4bit-qlora/blob/main/docs/SERVING-THROUGHPUT.md#throughput-census-bo7-measured-in-repo).
- **Platforms:** CUDA execution is the tested path. ROCm, macOS, Windows and other non-CUDA GPU execution are outside this package's scope.
