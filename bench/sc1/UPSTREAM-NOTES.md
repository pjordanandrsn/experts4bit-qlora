## e4b — experts4bit-qlora main `079a422`, grouped-nf4-gemm v0.34.1

- **Served engine.** Decode runs through `experts4bit_qlora/engines/paged_runner.py:PagedModelRunner` (greedy `argmax`, `paged_runner.py:148`; fp8 paged KV `engines/fp8_paged_kv.py:Fp8PagedKV` with `k_groups` 4 sub-row scales; `run_prefill` ingests `(rid, start, take)` chunks one sequence at a time as batch-1 forwards and flushes staged bf16 K/V to the FP8 pool when the prompt completes; `run_decode` with `enable_decode_graphs` pads the active set to a bucket of `{1, 2, 4, 8, 16}` (`paged_runner.py:38`) and replays that bucket's CUDA graph, with a per-step H2D of ids/pos and a host `.tolist()` readback (`paged_runner.py:301`)).
  - The scheduler is `engines/scheduler.py:ContinuousScheduler` (FIFO admission bounded by `max_seqs` AND `kv_slots`, `scheduler.py:175-185`; prefill preferred over decode, `:187-204`; `chunk_tokens` 512 default; `Request.ttft` from ARRIVAL incl. queue wait; CPU-tested with a fake runner, `tests/test_scheduler.py`).
- **The register's window number is NOT a scheduler number.** `bench/p39/step_decomp.py --b1d-loop graph --b1d-timed` (~2029-2200) times bare `g.replay()` calls between two `torch.cuda.synchronize()` — no scheduler step, no per-step H2D, no host readback, no detokenisation; the window arm captures its own single-step `torch.cuda.CUDAGraph` (`step_decomp.py:2036`) and never calls `enable_decode_graphs` (`paged_runner.py:209`). vLLM's slope (`p37_vllm.py`) includes its whole serving loop (P58 stated the asymmetry).
  - SC1's `lic_sched` arms time e4b through `ContinuousScheduler.step()` by the same 32→128 slope, built by the opt-in `experts4bit_qlora.serve_paged` module (`build_engine`; e4b#853 — named in the registered cut, L34). The shipped `serve.py` is FastAPI over HF `generate` at batch 1 and never constructs `PagedModelRunner` (#774) — not an arm.
- **EOS finding (found while building the server).** `PagedModelRunner.eos_id` is stored and never consulted (`paged_runner.py:57,62`); `ContinuousScheduler._emit` ended a request only at `max_new_tokens`, so every registered serving number ran to its fixed length (`ignore_eos` semantics). e4b#848 adds `add_request(..., stop_ids=, min_tokens=)` additively (default `None` = the old contract).
  - A benchmark against e4b WITH `ignore_eos` reads the same engine behaviour as before; one WITHOUT it is meaningful only on a build that includes #848 — the registered cut (`SC1-PREREG.md` L34) requires it. `Fp8PagedKV.append` raises inside an engine step when a sequence overflows `max_tokens_per_seq` (an engine fault for every resident request); the server refuses such requests at admission (400, never clamps).
  - A prefilling prompt's bf16 K/V is staged on the GPU until the prompt completes (VRAM ∝ concurrently prefilling tokens, unbudgeted); admission is FIFO, no eviction.
- **The int4 serving stack** (levers applied by `bench/p42/hook/usercustomize.py:135-154` right after `enable_hybrid_tier`; the hook touches no fold): `E4B_SERVE_EXP_INT4=1` int4-b32 expert stores (`engines/int4_experts.py:enable_serve_experts_int4`, RTN packer); `E4B_SERVE_EXP_INT4_CALIB=1` + `E4B_CALIB_NSEQ` + `E4B_CALIB_SOURCE` = per-expert GPTQ calibration, SEQUENTIAL over `E4B_CALIB_LAYERS_PER_PASS` chunks, dumped as a hash-pinned artifact (`E4B_INT4_DUMP_ARTIFACT_DIR`, `pack_manifest.verify_artifact`, `pack_fingerprint`) and loaded BY FINGERPRINT (`E4B_INT4_ARTIFACT_DIR` + `E4B_INT4_EXPECTED_FINGERPRINT`; a mismatch refuses, never rebuilds).
