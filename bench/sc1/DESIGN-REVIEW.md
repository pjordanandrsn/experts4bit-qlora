## Findings

1. **HIGH (quality instrument) — the served-shape NLL as written reads a logprob that a cached-prefix forward never computes; on SGLang it returns nothing, on vLLM it is absent for exactly the T == 1 cases.** Draft L59: "2048 requests each extending the prompt by ONE token with the engine's prefix cache ON, reading the last prompt token's logprob". The logprob of prompt token n−1 needs the logits at position n−2, which are the LAST CACHED position; a one-token extension recomputes position n−1 only. SGLang clips input logprobs to the uncached range (`upstream-sglang.md` L135: `resolved_start = max(logprob_start_len, prefix_len)`, "positions served from the radix cache return no logprob") — the row would be EMPTY, or the lane would turn the radix cache off and score prefill-shaped twice while labelling one copy T == 1. On vLLM V1 the prompt-logprob of token i comes from the logits at i−1 inside the processed range, so with a block-aligned cached prefix (every 16th request) the last prompt token has no logprob and the mean "recomputed suffix" can never read 1. P6's "< 0.002 nats on vLLM" would then be confirmed by an instrument that never left the prefill path — a check that could not have failed. *Fix:* score at the GENERATION position: prompt = `ids[:512+t]`, `max_tokens = 1`, and read log p(`ids[512+t]`) from the first generated position's distribution — vLLM `SamplingParams(logprobs=-1)` with `LLM(max_logprobs=-1)` (all-vocab logprobs are supported: `sampling_params.py:292-298, 840-841`; `config/model.py:254`; `logprobs_mode` default `raw_logprobs`, `:259`), SGLang `token_ids_logprob=[ids[512+t]]` + `max_new_tokens=1` (`upstream-sglang.md` L126), llama.cpp the libllama harness (L37, already planned), EXL3/LMDeploy direct logits or the same specified-token read. Teacher forcing holds by construction (the next prompt is the corpus prefix, the engine's token is discarded). Make the cache hit a VALIDITY predicate, not a note: vLLM `RequestOutput.num_cached_tokens` (`outputs.py:126,168`) and SGLang `meta_info.cached_tokens` must read ≥ n − block_size on every request after the first, else the row is relabelled `prefill-shaped (no cache hit)`; report the per-request suffix-length histogram (vLLM: 512 once, then 1..16 cycling; mean ≈ 8.5, never 1). Issue requests SEQUENTIALLY (one call each): 2048 prompts submitted together are scheduled before their predecessors' blocks are cached.
