# Frozen SC2 driver startup (proposal)

A live verified capacity wrapper derives only `sc2_warm`, `sc2_burst` and
`sc2_end`. Schema 3 pins its original native spec, stage, tools, handoff manifest,
held numeric loopback base and fresh component output. Each selected Python
`-I -S -B` child verifies installed bytes/startup/imports before entering the
unchanged staged SC2 driver. The registered builder regenerates every argument.

After return the child checks native plan/requests and common prompt bytes,
then rechecks imports, interpreter, installed/archive/tool/stage bytes and
search/environment state. The parent joins PID, spec/handoff/native hashes and
process cleanup. Exit zero alone refuses. Native bytes are copied unchanged to
the ordinary trace projection path. Plain unverified invocation stays explicit.

This component verifies driver startup composition only. Server startup,
listener ownership outside the existing capacity wrapper, GPU/context absence,
ABBA integration, fleet/launch gates and real installation remain separate.
No clearance or rental is authorized; all GPU/release/nested flags stay false.
