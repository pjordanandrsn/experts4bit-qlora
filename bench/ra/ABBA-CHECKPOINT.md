# ABBA checkpoint index composition

Schema 4 adds `checkpoint_authority: {"timeout_s": ...}` to the schema-3
ABBA plan. The supervisor derives every checkpoint manifest from its pinned
common-input spec, stage and reviewed input lock. There is no caller command,
model override, extra argument or launch CLI.

Eight fixed selected-Python `-I -S -B` processes bracket the four ABBA
positions, in addition to eight publication probes and 24 measured wrapper
processes. Each requires parent-death evidence, zero return, complete group
cleanup and matching manifest/PID/helper/input identities. The parent reparses
all four bounded retained Hub responses, independently binds the complete
local checkpoint and shard map, and compares results with the reviewed lock.
All positions must retain one common checkpoint identity. The timeout budget
includes all eight probes and the existing 600-second retrieval reserve.

The fixed worker inventory explicitly adds only `ra_checkpoint.py` (34 files);
unknown or missing tools still refuse. Fresh outputs, manifests, logs and
process receipts cannot overlap protected inputs or authority sources.
Failures retain the active gate and completed prefix without retrying.

`checkpoint_authority_verified` reports this component's Hub-index and local
file equality. Dataset/calibration authority, tokenizer execution, actual
model consumption, publisher signatures, native context absence, GPU engagement
and release/launch clearance remain unverified. Synthetic CPU controls are
not actual checkpoint or full-image installation evidence.
