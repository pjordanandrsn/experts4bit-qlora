# ABBA source and publication proposal

Schema 3 adds pinned `source_publication.manifests.old/new` and one `timeout_s`
to schema 2. Both manifests use the existing publication probe schema. Their
release archives must be the selected startup archives; the parser is the
frozen packaging archive. Proof requires the registered baseline commits,
versions and wheel hashes on both sides.

Each position has a fixed no-site publication process before and after its six
measured wrappers: eight additional processes. These run the unchanged
`ra_publication.py` with selected Python `-I -S -B`, without release imports or
site activation. The existing probe recomputes Git object addresses, runtime
payload mappings and dependency declarations, and surrounds source checks with
GitHub/PyPI records. The supervisor requires normal return, verified parent-death
guard and completed cleanup, joins source/parser/archive identities, and retains
all 16 bounded, clock-read response records per probe with exact hashes and a
complete receipt inventory.

Before/after identities must match, including each repeated version position.
Every measured worker's independently verified installed release versions and
wheel hashes must match that position's source/publication evidence. Common
payload comparisons remain separate. A failed probe or join preserves its raw
records, active phase and completed measured prefix. Publication timeouts enter
the whole-run budget; outputs and the advisory lock cannot overlap source,
parser, manifest, tool, archive or common input roots.

Completion remains `ORDERED_COMPONENTS_RECORDED_PENDING_GATES`. The component
flag `source_publication_verified` describes these joins only. GitHub-reported
signature validity is not local key trust. This proposal proves no reproducible
build, checkpoint/dataset authority, runtime input consumption, training feature
engagement, native context absence, full-image installation, GPU engagement or
release/launch clearance. No rental CLI is added.
